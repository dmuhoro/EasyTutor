# C11 — hosted proxy auth and per-learner daily cap proven at the real boundary

**Date:** 2026-11-25 · **Owner:** agent · **Status:** `VERIFIED-LOCAL`.

## Real boundary

`supabase/functions/ai-proxy/handler.ts` is the production request handler that
`index.ts` delegates to. It must:
1. reject an invalid JWT through Supabase auth **before** the cap RPC or Groq;
2. attribute the atomic cap increment to the **authenticated** learner, never
   to a caller-supplied `userId`;
3. refuse the 201st call with 429 and never reach the provider;
4. fail closed if the atomic cap RPC fails.

The registered acceptance `npm run check:ai-boundary` only proves there is no
disabled direct client rail. It cannot observe any of the four behaviours
above, so a regression could land green — a false-confidence gate
(Constitution Article I.1). Acceptance is repointed to the real-handler test.

## Red before green

`tests/flows/aiProxy.authCap.test.ts` was added with six assertions. Against
the shipped handler it is green (`6 passed`). As a negative control the cap
check line was temporarily removed from the handler and the run repeated:

```text
shipped:            Test Files 1 passed (1); Tests 6 passed (6)
cap check removed:  Test Files 1 failed (1); Tests 1 failed | 5 passed (6)
                    failed case: refuses the 201st call and never reaches the provider
```

The handler was restored byte-for-byte afterwards (`git diff --quiet` clean).
No assertion, timeout or threshold was weakened.

## What is proven

- invalid JWT (auth endpoint 401) → 401 `invalid jwt`, zero RPC and zero Groq calls;
- auth 200 with no usable `id` → 401, zero RPC and zero Groq calls;
- cap RPC body carries `p_user_id: learner-1`, never the caller's
  `attacker-controlled` value, and uses the service-role header while auth uses
  the anon key;
- call 200 → Groq called exactly once; call 201 → 429 and zero Groq calls;
- failing cap RPC rejects the request and never reaches Groq.

Only the network socket is stubbed; auth, the atomic RPC, allowlists and the
provider call are the unchanged production handler. This is local proof of the
code path, **not** a claim about live Groq validity (D05 remains blocked).
