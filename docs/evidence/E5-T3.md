# E5-T3 / GT-11 — RLS matrix enforced in CI, fail closed

**Date:** 2026-11-25 · **Owner:** agent · **Status:** `VERIFIED-LOCAL`
(the exact pushed green run is not claimed in this file).

## Real boundary

The repository had a *local* proof of tenant isolation but no CI enforcement:
`scripts/security/run_rls_matrix_local.sh` starts an isolated postgres:16 +
PostgREST, applies the committed `20261104_rls_hardening.sql` migration twice
(idempotency), seeds two learners, and runs 247 signed-JWT assertions through
the real PostgREST boundary. Nothing in `.github/workflows/ci.yml` ran it, so a
regression in the migration could land green. That is a false-confidence gate
(Constitution Article I.1).

The fix adds a dedicated `rls-matrix` CI job. It does not touch the existing
`build` or `real-stack` jobs and uses isolated container names/ports
(`et-rls-pg` / `et-rls-rest`, 55441 / 55443), so it cannot collide with
`supabase start` (54331).

## Red before green (negative control)

The harness proves it is not vacuous by running against
`fixtures/no_rls_baseline.sql` first:

```text
hardened:              rows=247 pass=247 fail=0  blocked=0  → exit 0
unhardened control:    rows=247 pass=70  fail=177 blocked=0 → exit 1
                       script converts that failure into a PASS of the control
```

The unhardened control failing 177 assertions is the recorded negative result:
remove the migration and the gate breaks. No assertion, threshold or timeout was
weakened.

## CI job

```yaml
rls-matrix:
  name: RLS matrix (247 assertions, fail closed)
  steps:
    - run: RLS_PROOF_UNHARDENED=1 bash scripts/security/run_rls_matrix_local.sh
    - run: bash scripts/security/run_rls_matrix_local.sh
```

Both steps must exit 0. A skipped, cancelled, timed-out or failing job is not a
pass; `scripts/readiness/check-pr-checks.mjs` requires every non-skipped check
to be green before merge.
